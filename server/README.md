# ДентИИ — сервер

Бэкенд для раздела «ДентИИ» в приложении Denvise. Отдельный маленький
Node.js/Express-сервис, который:

1. Собирает всю базу знаний Denvise (`data/procedures.ts`, `data/diagCases.ts`,
   `data/consultData.ts`) в один текстовый корпус.
2. Передаёт его модели в system-сообщении на каждый запрос через
   **OpenRouter** (единый OpenAI-совместимый API к Qwen, DeepSeek и другим
   моделям) — с жёсткой инструкцией отвечать только по этому корпусу,
   указывать источник и честно говорить «этого нет в базе», если ответа нет.
3. Отдаёт ответ мобильному приложению через один HTTP-эндпоинт.

Векторной БД сознательно нет: корпус сейчас ~55 источников, весь system-промпт
~43К токенов — он целиком помещается в system-сообщение. Даже без
prompt-кэширования это дёшево на моделях уровня DeepSeek/Qwen (~$0.004 за вопрос
на deepseek-v4-flash, ~$0.001 при попадании в кеш — см. `.env.example`). Когда база вырастет на порядок
(сотни протоколов, полные тексты учебников) — этот подход надо будет заменить
на настоящий retrieval (эмбеддинги + top-k поиск в `knowledgeBase.ts`), но пока
это преждевременная оптимизация.

## Важно: system-промпт НЕ гарантирует, что модель не сфантазирует

Никакой system-промпт не может технически заблокировать модели доступ к её
собственным весам — это просьба, а не песочница. Поэтому в дополнение к
промпту есть проверяемый слой:

1. Модель обязана закончить ответ строкой `Источники: #12, #34` — номера
   строго из тегов `[[Источник #N]]`, которые она видела в контексте
   (см. `systemPrompt.ts`).
2. Сервер (`citations.ts`) разбирает эту строку сам и проверяет каждый номер
   против реальной базы (`knowledgeBase.ts`) — название источника, которое
   видит врач, берётся из **наших** данных, а не из текста модели. Если
   модель сослалась на номер, которого нет, — это остаётся в `invalidNumbers`,
   ответ помечается `flagged: true`, и в лог сервера пишется предупреждение.
3. `GET /api/dentai/source/:number` отдаёт полный сырой текст источника —
   в приложении можно раскрыть карточку источника и свериться с оригиналом
   самостоятельно, а не верить пересказу модели на слово. Это самая надёжная
   защита из всех, потому что не зависит от того, ведёт ли себя модель
   ожидаемо.

Чего эта проверка **не** делает: она не проверяет, что содержание ответа
действительно соответствует тексту источника с указанным номером (модель
может сослаться на реальный источник, но пересказать его неточно). Для этого
нужен второй вызов модели-судьи, сверяющий ответ с текстом источников — это
осознанно не сделано в MVP, но следующий шаг, если `flagged: true` в логах
станет появляться часто.

## Почему OpenRouter, а не провайдер напрямую

OpenRouter — это один OpenAI-совместимый эндпоинт
(`https://openrouter.ai/api/v1/chat/completions`) к сотням моделей разных
провайдеров, включая Qwen (Alibaba) и DeepSeek. Плюсы для этого проекта:

- один ключ и один биллинг вместо отдельного аккаунта на каждого провайдера;
- модель переключается одной строкой в `.env` (`OPENROUTER_MODEL`) — можно
  на лету сравнить Qwen и DeepSeek на одних и тех же вопросах врача, без
  правки кода;
- код завязан на стандартный `openai` npm-пакет (просто другой `baseURL`),
  а не на специфичный SDK — если решите добавить ещё одного провайдера или
  уйти с OpenRouter, менять почти нечего.

Минус, о котором стоит знать: для DeepSeek/Qwen кеш промпта через OpenRouter
не гарантирован — он зависит от того, к какому провайдеру OpenRouter направит
запрос, и живёт недолго. Замер в сентябре 2026: попадание в кеш удешевляет
вопрос ~в 4 раза, но повтор через 10 минут в кеш не попал. Реальную долю
попаданий показывают логи `llm_usage` (поле `cachedTokens`). Если корпус
сильно вырастет — это одна из причин пересмотреть архитектуру (см.
`knowledgeBase.ts`).

## Почему не сразу учебники (Максимовский, Боровский и т.п.)

Экран `dentai.tsx` в приложении обещает ответы «по Максимовскому, Боровскому,
протоколам МЗ РФ» — это реальные учебники под авторским правом, их нельзя
просто оцифровать и залить в базу без лицензии. Сейчас агент отвечает **только
по собственным данным Denvise** (протоколы/случаи/скрипты, которые уже
написаны в проекте) — это безопасно с точки зрения прав. Вопрос лицензирования
реальных учебников/протоколов МЗ РФ — отдельная задача, не техническая.
До её решения стоит либо скорректировать текст на экране `dentai.tsx`, либо
явно писать в ответах агента, что источник — методология Denvise, а не
конкретные учебники.

## Запуск локально

```bash
cd server
npm install
cp .env.example .env
# впишите свой OPENROUTER_API_KEY в .env (получить: https://openrouter.ai/settings/keys)
npm run dev
```

Сервер поднимется на `http://localhost:8787`. Проверить:

```bash
curl http://localhost:8787/health
```

## Выбор модели: Qwen vs DeepSeek

Переключается одной строкой `OPENROUTER_MODEL` в `.env` — см. актуальные id
и цены в комментариях `.env.example`. Коротко:

- **DeepSeek V4 Flash** (по умолчанию) — дешевле всего, 1M контекста, хорошо
  подходит как стартовый вариант для этой задачи (грounded QA по короткому
  корпусу — не нужен топовый reasoning).
- **DeepSeek V4 Pro** — сильнее в сложных многоходовых рассуждениях, дороже.
- **Qwen3.6 Plus / Flash** — альтернатива от Alibaba, тоже 1M контекста.

Что реально лучше отвечает по-русски на клинические вопросы из вашего корпуса —
надёжнее всего проверить на паре десятков реальных вопросов от практикующих
врачей, а не полагаться на общие рейтинги моделей (те чаще всего меряют
английский и код/математику, а не русскоязычную клиническую точность). Смените
`OPENROUTER_MODEL`, перезапустите сервер и сравните ответы на одних и тех же
вопросах.

## API

### `POST /api/dentai/ask`

```json
{
  "messages": [
    { "role": "user", "content": "Какая дифдиагностика между кариесом дентина и острым пульпитом?" }
  ]
}
```

- `messages` — вся история диалога (макс. 20 сообщений, каждое до 4000
  символов), последнее сообщение обязательно `role: "user"`.
- Для нового вопроса в существующем чате просто добавляйте новые сообщения в
  конец массива и присылайте весь массив целиком (модель без сервера не
  хранит состояние диалога).

Ответ:

```json
{
  "answer": "Текст ответа...",
  "sources": [
    { "number": 20, "source": "diagCases", "title": "Кариес в стадии пятна (K02.0)" },
    { "number": 21, "source": "diagCases", "title": "Кариес дентина (K02.1)" }
  ],
  "flagged": false,
  "model": "deepseek/deepseek-v4-flash",
  "usage": {
    "promptTokens": 43403,
    "cachedTokens": 37456,
    "completionTokens": 534,
    "totalTokens": 43937,
    "costUsd": 0.001113424
  }
}
```

- `sources` — только те номера источников, которые сервер сам проверил против
  базы; названия берутся из наших данных, а не из текста модели.
- `flagged: true` — модель сослалась на несуществующий номер источника или не
  указала источники вообще. Стоит показать это врачу как предупреждение
  (уже сделано в `dentai.tsx`), а не скрывать.

### `GET /api/dentai/source/:number`

Отдаёт полный сырой текст конкретного источника — для самопроверки:

```json
{ "number": 20, "source": "diagCases", "title": "...", "text": "Клинический случай: ..." }
```

### `GET /health`

Проверка живости + статистика базы знаний. Полезно для мониторинга и для
отладки при добавлении новых протоколов/случаев — сразу видно, что данные
подтянулись и структура файла не сломалась.

## Проверка целостности данных

Перед сборкой корпуса стоит убедиться, что массивы данных не содержат «дыр»
(например, от случайных двойных запятых при правке `data/*.ts` вручную) —
`.map()` по массиву с `undefined`-элементами уронит и сборку корпуса, и рендер
в приложении. Быстрая проверка:

```bash
npm run kb:stats
```

выведет количество источников по каждому файлу — если число резко разошлось
с ожидаемым после правки `data/procedures.ts` / `data/diagCases.ts` /
`data/consultData.ts`, значит где-то пропущена или задвоена запятая.

## Деплой

Это обычный stateless Express-процесс — подойдёт любой Node-хостинг
(Railway, Render, Fly.io, VPS + pm2, и т.п.):

```bash
npm install
npm start
```

`npm start` запускает `src/index.ts` напрямую через `tsx` (без отдельного шага
компиляции — сборка через `data/*.ts` вне `server/` даёт неудобную структуру
`dist/`, а для сервиса такого размера отдельный build-артефакт не нужен).
`npm run typecheck` — прогнать проверку типов отдельно (например, в CI перед
деплоем).

Не забудьте:
- `OPENROUTER_API_KEY` — только на сервере, никогда не в мобильном приложении;
- задать `CORS_ORIGIN`, если появится веб-клиент;
- после деплоя обновить `API_BASE_URL` в `constants/config.ts` в мобильном
  приложении на реальный URL сервера.
