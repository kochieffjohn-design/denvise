# Миграция Denvise в веб (PWA)

План зафиксирован 29.09.2026 по итогам обсуждения. Цель — запуститься как платный веб-сервис вместо публикации в App Store / Google Play, сохранив возможность вернуться в сторы позже.

## 1. Клиент

- **Та же кодовая база**: Expo Router + React Native Web. `react-native-web` и `react-dom` уже в зависимостях, экраны написаны на обычных RN-примитивах — переписывать не нужно.
- **Должно выглядеть как приложение** — без этого не запускаемся. Ориентир — keenee.app. Критерии готовности:
  1. Устанавливается как PWA: манифест, иконки, сплэш, режим standalone без адресной строки.
  2. Нижние табы, учтены safe-area/«чёлка»; все `Platform.OS === 'ios' ? 54 : 44` заменены на safe-area.
  3. Нет зума при фокусе в поле (шрифт полей ≥ 16px), нет «резинки» страницы.
  4. Нет выделения текста на UI, мгновенный визуальный отклик на нажатие.
  5. Анимации переходов, скелетоны вместо спиннеров, обработка отсутствия сети.
  6. 60 fps при прокрутке.
  7. На десктопе — приложение по центру шириной ~480px на брендовом фоне.
- Приёмка на реальных устройствах: iPhone (Safari и установленное PWA) и Android (Chrome).
- Офлайн на запуске: оболочка приложения и бесплатный контент из бандла.
- Порядок первого входа: онбординг → вход → приложение.

## 2. Архитектура бэкенда

Разделение продиктовано 152-ФЗ: первичный сбор и хранение персональных данных — на территории РФ.

```
Клиент (PWA, denvise.ru)
   │  все запросы
   ▼
Ядро — Yandex Cloud (РФ)
   • Postgres: пользователи, подписки, прогресс, попытки, банк аккредитации
   • авторизация, подписки, вебхуки ЮKassa
   • лимиты по пользователю, выдача платного контента
   • push, админка, события аналитики
   │  только текст диалога, без идентификаторов пользователя, по секретному ключу
   ▼
LLM-шлюз — Railway (текущий server/)
   • llm.ts, systemPrompt.ts, citations.ts, knowledgeBase.ts — почти без изменений
   • ничего не хранит
   ▼
OpenRouter (deepseek/deepseek-v4-flash)
```

Изменения в шлюзе: логирование токенов, закешированных токенов и стоимости; SSE-стриминг; доступ только от ядра (CORS/ключ); лимиты по IP заменяются лимитами по пользователю в ядре.

**Риск: домены `*.railway.app` недоступны из России** (обнаружено 30.09.2026). Тестовый стенд не открывается на телефоне без VPN, и даже с VPN, выходящим через Россию; открывается только через зарубежный узел. Следствия:
- Всё, к чему телефон пользователя обращается напрямую, должно быть в РФ: статика клиента и ядро — в Yandex Cloud под `denvise.ru`. Railway для пользователя становится невидим.
- Сейчас ДентИИ и ИИ-Пациент (и в мобильном приложении тоже) ходят в шлюз на Railway прямо с устройства — у пользователей из РФ без VPN они уже не работают. Это исправляется только переходом на схему «клиент → ядро → шлюз».
- **Проверено 01.10.2026** (Cloud Function в ru-central1, внешний IP 84.201.183.40, RU): Yandex Cloud → шлюз на Railway — работает (≈350 мс); Yandex Cloud → OpenRouter — **403 «Access denied by security policy»**, и на список моделей, и на запрос к модели. Значит:
  - ядро не может обращаться к модели напрямую — только через шлюз; **шлюз обязан оставаться за рубежом** (переносить его в Yandex Cloud нельзя);
  - шлюз — критическая точка: держать готовый запасной вариант на другом зарубежном хостинге (шлюз ничего не хранит, перенос — порядка часа) и мониторить доступность Railway из Yandex Cloud;
  - **вопрос юристу:** текст диалогов уходит за рубеж (без идентификаторов, но студент может вписать данные пациента) — нужно ли уведомление о трансграничной передаче; в интерфейсе ДентИИ/Пациента и в оферте — предупреждение не вводить персональные данные пациентов.

## 3. Авторизация

- Вход обязателен, без паролей: код на email, Яндекс ID, VK ID, Telegram Login. Реализация: Better Auth + собственный обработчик Telegram.
- Аккаунты склеиваются по совпадающему email. Telegram привязывается вручную в профиле. При входе через Telegram просим email — он нужен для чеков.
- Сессии: httpOnly-cookie в вебе; для будущего нативного приложения ядро выдаёт токены.

## 7. ДентИИ и ИИ-Пациент

- **Стриминг (SSE)** для обоих. Источники `#N` и признак `flagged` приходят в финальном событии, потому что `citations.ts` проверяет цитаты по полному тексту.
- `flagged` — жёлтая плашка под ответом: «Часть ответа не подтвердилась источниками».
- ИИ-Пациент, Экзамен и Диагностика от корпуса ДентИИ не зависят (Пациент получает только промпт персоны, остальные разделы не обращаются к серверу) — так и остаётся.

### База знаний ДентИИ (решено 29.09.2026)

Весь корпус больше не вставляется в промпт: в базу добавляются учебники большого объёма (права на использование, включая показ рисунков, подтвердил юрист).

**Поиск (RAG).** Смысловой поиск (pgvector) + поиск по точным словам (полнотекстовый поиск Postgres — коды МКБ, препараты, дозировки) + переформулировка вопроса моделью в 2–3 поисковых запроса с учётом истории диалога. База — в Postgres ядра (Yandex Cloud), отдельной схемой; поиск делает ядро, в шлюз уходят только вопрос и найденные фрагменты. Пилот — локально, не дожидаясь ядра. Модель эмбеддингов выбирается сравнением на тестовом наборе.

**Корпус.** Учебники + справочные данные проекта (протоколы, неотложка) — всё через поиск. Тренажёрные кейсы, квизы и банк аккредитации в корпус не входят.

**Обработка источников.**
- PDF с текстом и сканы распознаются моделью, которая «видит» страницу, в размеченный текст (заголовки, списки, таблицы). Все таблицы с цифрами и случайные 3–5% страниц владелец сверяет с оригиналом на странице сравнения.
- Нарезка по структуре книги (глава → раздел → подраздел), фрагменты ~300–600 токенов, таблица не режется. У фрагмента хранится адрес: книга, глава, раздел, страница.
- Схемы хранятся картинкой с подписью; описание, сгенерированное моделью, используется только для поиска и не цитируется. Если схема относится к вопросу — картинка показывается под ответом.
- Карточка книги (заполняет владелец): автор, название, издание, год, гриф, содержательные страницы, приоритет 1–3.

**Строгость ответа.**
- Нет ответа в источниках → честный отказ + запись вопроса (без данных пользователя) в журнал отказов; журнал — в админке.
- К каждому утверждению модель прикладывает скрытую дословную цитату; сервер проверяет её по тексту указанного фрагмента (без учёта ё/е, переносов, пробелов). Неподтверждённое утверждение удаляется, под ответом — жёлтая плашка. Это развитие текущего `citations.ts`, который проверяет только существование номера.
- Источники можно сочетать. При противоречии — обе позиции, в конце пометка из карточек: какое издание новее и какой источник приоритетный. Расхождения пишутся в журнал для владельца и врача.
- Поиск недоступен → ДентИИ не отвечает («сервис временно недоступен»).

**Отображение.** Ответ структурированный (заголовки, списки, таблицы) — в `dentai.tsx` нужно отображение Markdown, сейчас там простой текст. Под ответом — «Источники: <названия учебников>»; страницы и текст фрагментов пользователю не показываются, хранятся для отладки и тестов.

**Цена и модель.** ~12 фрагментов × ~450 токенов + правила + история ≈ 10 тыс. входных токенов → ~0.1 ₽ за вопрос, потолок 0.2 ₽. Модель — самая дешёвая из прошедших тестовый набор.

**Тестовый набор.** 40–50 вопросов владельца в формулировках студента, у каждого — книга и страница ответа или «в учебниках нет» (5–10 таких). Порог: ноль выдуманных утверждений, ≥ 90% правильных ответов, отказ на всех вопросах без ответа в базе. Поиск и ответ оцениваются отдельно.

**Пилот.** 2 учебника по терапевтической стоматологии (один PDF с текстом, один скан) из `C:\Projects\denvise-kb\` (вне репозитория). Идёт параллельно с этапом 2.

**Открыто:** как добавлять учебники после пилота — вручную через Claude или загрузкой в админке (решим при начале работ).

## 8. Экономика

Цифры ниже — замер по логам шлюза `llm_usage` 29.09.2026 на `deepseek/deepseek-v4-flash`. Цены $0.09 / $0.18 за 1M токенов (вход/выход) подтвердились. Курс условный, ~95 ₽/$.

- Вопрос к ДентИИ: ~43 тыс. входных токенов → ~$0.004 ≈ **0.40 ₽ без кеша**.
- Кеш промпта у DeepSeek срабатывает автоматически: при попадании ~37 из 43 тыс. токенов берутся из кеша, вопрос стоит ~$0.001 ≈ **0.10 ₽** (в ~4 раза дешевле).
- Попадание в кеш не гарантировано: повтор через 10 минут в кеш не попал, через 4 минуты — попал. Пока нет данных с продакшена, в расчётах закладываем цену без кеша; долю попаданий берём из логов (`cachedTokens > 0`).
- После перехода на поиск по базе знаний (§7) в промпт идёт ~10 тыс. токенов вместо 43 тыс.: ~0.1 ₽ за вопрос, потолок 0.2 ₽.
- Реплика ИИ-Пациента: ~$0.0002 ≈ **0.02 ₽** (~340 входных токенов, корпус не используется).
- С подписки за 490 ₽ после эквайринга (~3.5%) и налога (6%) остаётся ~440 ₽.
- Риск — злоупотребление ДентИИ, поэтому лимиты 3 и 100 в день.

Как получить точные цифры:
1. ~~Шлюз логирует реальные токены, кеш и стоимость каждого запроса.~~ Сделано: JSON-строка `type: "llm_usage"` на каждый вызов модели.
2. Собираем постоянные расходы: Yandex Cloud, Railway, email-рассылка, домен.
3. Строим калькулятор: пользователи, конверсия, запросов на пользователя, доля кеша, курс, цена → прибыль и точка безубыточности.
4. В день запуска ставим месячный лимит расходов в OpenRouter и алерт по дневному расходу.

## 15. Тестовый веб-стенд (Railway)

Адрес: https://denvise-web-production.up.railway.app — готовая сборка ветки `sdk-57-upgrade` для проверки на телефонах. **Открывается из России только через VPN с зарубежным узлом** (см. риск в §2), поэтому годится только для внутренних проверок — бета-тестерам его не давать. Ссылка публичная: не раздавать широко, пока нет входа и тарифов (весь контент в бандле, запросы к ДентИИ стоят денег).

Сервис `denvise-web` в том же проекте Railway, что и шлюз; `main` и шлюз не затрагивает. Config-as-code для новых сервисов Railway больше не включает (с 28.08.2026), поэтому всё задано в настройках сервиса:

- Source → Branch: `sdk-57-upgrade`; Root Directory — пусто (корень репозитория).
- Build Command: `npx expo export -p web`
- Start Command: `npx --yes serve@14 --single dist --listen $PORT` (`--single` — любой путь отдаёт `index.html`, иначе прямые ссылки вроде `/dentai` дают 404).
- Watch Paths: `/app/**`, `/assets/**`, `/components/**`, `/constants/**`, `/data/**`, `/hooks/**`, `/public/**`, `/.env`, `/app.json`, `/package.json`, `/package-lock.json`.
- Без своих команд Railway запускает `npm start` = `expo start` (сервер разработки) — `npm start` не менять, это команда локальной разработки.
- Адрес шлюза берётся из `.env` в репозитории (`EXPO_PUBLIC_DENTAI_API_URL`); `CORS_ORIGIN` шлюза сейчас `*`.
